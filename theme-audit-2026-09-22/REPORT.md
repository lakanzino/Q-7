## خلاصه نتیجه

فایل ZIP بدون خطای فشرده‌سازی استخراج شد. بسته شامل یک پوشه نصب‌پذیر `quantum-pedia-child/` و ۳۲ فایل بود. ساختار قالب حفظ شد و هیچ فایل سالم، فونت، تصویر یا قالبی حذف یا جابه‌جا نشد.

ده فایل با دلیل مشخص اصلاح شدند. مهم‌ترین اصلاحات عبارت‌اند از همگام‌کردن بلوک‌های گوتنبرگ با رندر PHP، افزودن بلوک جاافتاده دانشمندان، اصلاح HTML فهرست مطالب، جلوگیری از اجرای دوباره shortcodeها، امن‌سازی چند خروجی و ورودی، بهبود دسترس‌پذیری پنجره جست‌وجو، اصلاح fallback لوگوی Schema و یکسان‌سازی نسخه و مستندات.

## ایرادهای قطعی رفع‌شده

### ۱. ناهماهنگی بلوک‌های ویرایشگر و PHP

ویژگی‌های ثبت‌شده در `assets/js/blocks.js` با ویژگی‌های ثبت‌شده و مصرف‌شده در `functions.php` یکسان نبودند. در نتیجه تنظیماتی مانند شماره بخش، یادداشت، نمایش زیردسته‌ها و نمایش خلاصه نمی‌توانستند به‌طور قابل اتکا به رندر سمت سرور برسند.

**رفع:** ویژگی‌های چهار بلوک بین JavaScript و PHP همگام شدند و آزمون مقایسه نام بلوک‌ها موفق بود.

### ۲. نبود بلوک دانشمندان در JavaScript

PHP بلوک `qp/scientists` را ثبت می‌کرد، ولی JavaScript ویرایشگر آن را ثبت نمی‌کرد؛ بنابراین بلوک در درج‌کننده ویرایشگر قابل انتخاب نبود.

**رفع:** بلوک دانشمندان با تنظیمات عنوان، شماره، یادداشت، تعداد و ترتیب به ویرایشگر اضافه شد.

### ۳. نسخه ثابت و قدیمی دارایی‌های بلوک

نسخه JavaScript و CSS بلوک‌ها به‌صورت ثابت `1.6.0` ثبت شده بود و می‌توانست پس از به‌روزرسانی باعث استفاده مرورگر از نسخه cache‌شده شود.

**رفع:** نسخه دارایی‌ها از `filemtime()` گرفته می‌شود و در صورت نبود فایل از نسخه قالب استفاده می‌شود.

### ۴. HTML نامعتبر فهرست مطالب

سازنده TOC در توالی‌هایی مانند چند H2 پشت سرهم، تگ‌های `<li>` را کامل نمی‌بست. همچنین جایگزینی مبتنی بر `str_replace` می‌توانست برای تیترهای کاملاً یکسان شناسه تکراری تولید کند.

**رفع:** پردازش تیترها با callback انجام می‌شود، شناسه موجود و معتبر حفظ می‌شود، شناسه تکراری جایگزین می‌شود و ساختار H2/H3 با تگ‌های بسته تولید می‌شود.

### ۵. اجرای دوباره shortcodeهای مقاله

محتوا ابتدا از فیلتر `the_content` عبور می‌کرد و سپس دوباره به `do_shortcode()` داده می‌شد. فیلتر استاندارد WordPress خود shortcodeها را اجرا می‌کند.

**رفع:** اجرای دوم حذف شد تا shortcode خروجی‌شده دوباره و ناخواسته اجرا نشود.

### ۶. خروجی بدون محدودسازی محتوای دانشمند

خروجی فیلترشده `the_content` مستقیماً echo می‌شد.

**رفع:** خروجی نهایی با `wp_kses_post()` محدود شد؛ HTML مجاز محتوای WordPress حفظ می‌شود.

### ۷. fallback شکسته لوگوی Schema

اگر Site Icon تنظیم نشده بود، Schema به مسیر فرضی `/wp-content/uploads/logo.png` اشاره می‌کرد؛ چنین فایلی داخل بسته وجود ندارد و وجود آن در سایت قابل اثبات نبود.

**رفع:** fallback به لوگوی واقعی موجود در قالب، یعنی `assets/images/qpedia-logo-neon.png`، تغییر کرد.

### ۸. دسترس‌پذیری پنجره جست‌وجو

پنجره دارای `role="dialog"` و `aria-modal="true"` بود، اما کلید Tab می‌توانست فوکوس را از modal خارج کند. بستن پنجره نیز مقدار قبلی `body.style.overflow` را حفظ نمی‌کرد.

**رفع:** حلقه فوکوس برای Tab و Shift+Tab اضافه و مقدار قبلی overflow بازیابی شد. Escape و بازگرداندن فوکوس به دکمه بازکننده حفظ شدند.

### ۹. محافظ دسترسی مستقیم و ترجمه فرم جست‌وجو

`searchform.php` برخلاف دیگر فایل‌های PHP محافظ `ABSPATH` نداشت و دو رشته آن از توابع ترجمه استفاده نمی‌کردند.

**رفع:** محافظ دسترسی مستقیم و توابع escaping/translation مناسب اضافه شدند.

### ۱۰. ورودی مسیر و ویژگی دسترس‌پذیری

مقادیر `REQUEST_URI` پیش از پردازش مسیر به‌طور کامل sanitize نشده بودند. همچنین عنوان نوشته مستقیماً داخل `aria-label` چاپ می‌شد.

**رفع:** ورودی مسیر با `sanitize_text_field()` پس از `wp_unslash()` پاک‌سازی و عنوان ویژگی با `the_title_attribute()` تولید شد.

### ۱۱. نویسه خراب فارسی

در توضیح دسته `history-experiments` عبارت «آزمایش‌هایی ک�� فهم ما...» دارای نویسه جایگزین خراب بود.

**رفع:** عبارت به «آزمایش‌هایی که فهم ما...» اصلاح شد.

### ۱۲. نسخه و مستندات ناسازگار

نسخه قالب `1.7.2` بود، اما `readme.txt` هنوز Stable tag برابر `1.5.0` و Tested up to برابر `6.5` داشت و وجود منوی هدر حذف‌شده را ادعا می‌کرد.

**رفع:** نسخه به `1.7.3` افزایش یافت، اطلاعات readme همگام و تغییرات نسخه جدید ثبت شد.

## فایل‌های بررسی‌شده و بدون تغییر

قالب‌های `header.php`، `footer.php`، `page-homepage.php`، `single.php`، `taxonomy-quantum_category.php` و فایل‌های stub واژه‌نامه بررسی شدند و خطای قطعی نیازمند تغییر در آن‌ها یافت نشد.

فایل‌های CSS از نظر syntax، RTL، فونت داخلی، focus و reduced motion بررسی شدند. parser خطایی گزارش نکرد و تغییری که بدون مشاهده سایت بتوان سود آن را قطعی دانست یافت نشد؛ بنابراین ظاهر سایت بازطراحی نشد و CSS دست‌نخورده ماند.

فونت‌ها و تصاویر حذف یا تبدیل نشدند. تصویر لوگو `512×512` و screenshot برابر `1200×896` است.

## محدودیت‌های قطعی بررسی

- PHP CLI در محیط موجود نبود؛ بنابراین `php -l` اجرا نشد. نتیجه parser استاتیک جایگزین این واقعیت گزارش نشده است.
- Composer، PHPCS/WPCS، PHPStan و WP-CLI در محیط موجود نبودند؛ بنابراین اجرای آن‌ها ادعا نمی‌شود.
- قالب والد `quantum-pedia` در بسته نبود؛ سازگاری runtime با نسخه واقعی والد قابل اثبات نیست.
- WordPress اجرایی، پایگاه داده و داده تنظیمات سایت در محیط وجود نداشت؛ فعال‌سازی واقعی قالب، rewriteها، queryها و خروجی Schema در runtime آزموده نشد.
- مرورگر متصل به WordPress وجود نداشت؛ ظاهر واقعی، کنتراست نهایی محاسبه‌شده، CLS و رفتار responsive به‌صورت دیداری آزموده نشد.
- علت وجود نوع‌های محتوایی در قالب به‌جای افزونه از فایل‌ها قابل تشخیص نیست. انتقال آن‌ها بدون برنامه مهاجرت می‌تواند سایت را خراب کند؛ بنابراین انجام نشد.
- وجود افزونه SEO در سایت مشخص نیست. اگر افزونه‌ای مانند Yoast فعال باشد، متاتگ‌های داخلی قالب ممکن است با آن هم‌پوشانی داشته باشند؛ بدون فهرست افزونه‌های فعال نمی‌توان حذف قطعی انجام داد.

## مهارت‌های استفاده‌شده

- `wordpress-router`: تشخیص قالب فرزند کلاسیک و انتخاب مسیر بررسی مناسب.
- `wp-project-triage`: موجودی قطعی فایل‌ها، نسخه‌ها، وابستگی‌ها و قابلیت‌ها.
- `wp-block-development`: بررسی و اصلاح ثبت بلوک‌های داینامیک و تطابق JavaScript/PHP.
- `wp-performance`: بررسی enqueue، نسخه cache و queryهای اصلی؛ اصلاح نسخه‌گذاری دارایی‌های بلوک.
- `wp-phpstan`: استفاده از اصول بررسی نوع و null؛ خود PHPStan به علت نبود PHP/Composer اجرا نشد.
- `no-ai-slop`: پاک‌سازی مستندات و رشته خراب بدون تغییر لحن یا ادعای تازه.

مهارت‌های زیر پس از بررسی **فعال نشدند**:

- `wp-block-themes`: قالب Block Theme و `theme.json` وجود ندارد.
- `wp-patterns`: فایل pattern وجود ندارد.
- `wp-interactivity-api`: هیچ directive یا API مرتبطی وجود ندارد.
- `wp-rest-api`: route سفارشی وجود ندارد.
- `wp-wpcli-and-ops`: WP-CLI و WordPress اجرایی موجود نیست.
- `wp-plugin-directory-guidelines`: بسته قالب است، نه افزونه ارسالی به WordPress.org.
