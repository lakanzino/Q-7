### قانون ۲ — سیستمِ طراحی (Design System) مینیمال

#### ۲.۱ گریدِ ۸ پیکسلی (8px Grid)

- کلیدی‌ترین قانونِ مینیمال: **تمام** فاصله‌ها، اندازه‌ها و موقعیت‌ها مضربی از ۸ باشند: `8, 16, 24, 32, 48, 64, 120`.
- نتیجه: ریتمِ بصریِ منظم + کارِ آسان‌ترِ توسعه.

#### ۲.۲ فضایِ سفید (Whitespace)

- فضایِ سفید یک **عنصرِ فعال** است، نه فضایِ خالی.
- بینِ بخش‌هایِ اصلی: **≥ ۳۲px**.
- بخش‌هایِ کلیدی مثل Hero: **۴۸ تا ۱۲۰px**.

#### ۲.۳ تایپوگرافی با کنتراستِ بالا

- تمایزِ بصری از طریقِ **وزن و اندازه** است، نه رنگِ زیاد.
- فونت‌هایِ Sans-serif هندسی: Inter، SF Pro، Helvetica Neue.
- متنِ بدنه: حداقل **16px** (ترجیحاً 18px).
- مقیاسِ تیترها: **48 → 32 → 24 → 18px**.

#### ۲.۴ ترکیب‌بندی (Layout)

- Flexbox / CSS Grid با gapهایِ بزرگ.
- عرضِ محتوا محدود: مثلاً **max-width: 800px** برای مقالات (خطوطِ متنِ خیلی بلند نه).

#### ۲.۵ کادرها و کارت‌ها

- کارت‌ها حجیم و زرق‌وبرق نباشند.
- سایه‌هایِ بسیار نرمِ چندلایه (box-shadow با رنگِ شفاف) به‌جای سایه‌هایِ تند.
- گلاسمورفیسم **بسیار ملایم** (پس‌زمینهٔ نیمه‌شفاف + `backdrop-filter: blur(8px)`) فقط برای کارت‌هایِ شاخص — خواناییِ متنِ رویِ آن حفظ شود.

#### ۲.۶ دکمه‌ها

- ترنزیشن: `transition: all 0.2s ease-in-out` (بدونِ تغییرِ ناگهانی).
- Hover: عمقِ سایه کمی بیشتر **یا** پس‌زمینه ← `#F4A261`.
- حسِ فیزیکیِ ملایم: `transform: scale(1.02)`.

#### ۲.۷ انیمیشن‌هایِ ورودی

- Fade-in + Slide-up با تأخیرهایِ کوتاهِ **Stagger: ۴۰–۸۰ms** برای کارت‌هایِ یک بخش.

#### ۲.۸ تکنیک‌هایِ سبک (الهام از Stripe / Linear / Vercel)

1. **Micro-transitions:** خیلی سریع — دکمه/لینک: **150ms ease-out**؛ المان‌هایِ ریز: **80–120ms**؛ بدونِ انیمیشنِ تزئینی.
2. **Subtle Lift:** `translateY(-4px)` + سایهٔ نرم در Hover کارت/دکمه.
3. **Cursor-tracked Radial Glow:** لایهٔ شفافِ رویِ کارت + ردیابیِ مختصاتِ موس با JS + `radial-gradient` ملایم با `#F4A261` — فقط opacity و gradient تغییر می‌کند (سبک).
4. **Content Reveal on Scroll:** با `IntersectionObserver`: `opacity 0→1` + `translateY(10px)→0`. **ممنوعیت:** هرگز متنِ اصلیِ مقاله با انیمیشنِ اسکرول مخفی نشود (خوانایی)؛ فقط تصویر، آیکون و کارت.
5. **Ambient:** برای پس‌زمینه/دکوراتیو — خیلی کند و بی‌پایان؛ مثلاً گرادیانی که در ~۸ ثانیه آرام تغییر می‌کند.

#### ۲.۹ جدولِ زمان‌بندیِ مرجع

| رویداد | زمان |
|---|---|
| فیدبکِ کلیک (Press) | ≤ 100ms |
| Hover دکمه/لینک | 100–150ms |
| Hover کارت | 150–200ms |
| باز شدنِ منو/تب | 100–300ms |
| ورودِ مودال | 200–300ms |
| خروجِ مودال | 200–250ms |
| ترنزیشنِ بینِ صفحات | 150–200ms |

### قانون ۳ — UX و میکرو-تعاملات (Micro-interactions)

اصل: هر عنصر باید **دلیلی** برای وجودِ داشتن داشته باشد.

#### ۳.۱ ناوبری و ساختار

1. **هدرِ چسبان با افکتِ شیشه‌ای:** هنگامِ اسکرول ثابت بماند؛ پس‌زمینه = لایهٔ نیمه‌شفاف با `backdrop-filter: blur(12px)` و شفافیتِ **۸۰٪ از `#E8F6FF`**.
2. **Breadcrumb مینیمال:** مسیرِ مقاله (خانه > مقالات > ...) با فونتِ **14px** و رنگِ `#3BA7F2`.
3. **جستجویِ هوشمند (Command Palette):** آیکونِ ذره‌بینِ کوچک + پنجرهٔ مینیمال با کلیک یا **Ctrl+K**.
4. **منویِ موبایلِ تمام‌صفحه:** پس‌زمینه `#0B3D91` + انیمیشنِ Fade-in.

#### ۳.۲ ارائهٔ محتوا و داده‌هایِ علمی

1. **نوارِ پیشرفتِ مطالعه:** بالایِ صفحهٔ مقاله، ~**3px**، رنگِ `#F4A261`، با اسکرول پر می‌شود.
2. **زمانِ مطالعه:** کنارِ عنوان، با آیکونِ ساعت: «۵ دقیقهٔ مطالعه».
3. **تولتیپ‌هایِ علمی:** هاور روی اصطلاح/فرمول → باکسِ کوچکِ سفید + سایهٔ نرم + متن `#333333`.
4. **نمودارهایِ مینیمال:** خطی/میله‌ایِ ساده با `#3BA7F2` + `#F4A261`؛ خطوطِ شبکه حذف یا بسیار کم‌رنگ.

#### ۳.۳ فرم‌ها و ورودی‌ها

1. **استایلِ خط‌محور:** به‌جای باکسِ بزرگ، فقط یک خطِ زیرین؛ Focus → خط به `#3BA7F2` + Floating Label به بالا.
2. **اعتبارسنجیِ درجا (Inline):** پیامِ خطا **زیرِ همان فیلد**، کوچک و ملایم (قرمزِ ملایم / کهربایی برای هشدار).
3. **دکمه‌هایِ شبح (Ghost):** پس‌زمینهٔ شفاف + بوردرِ نازک — فقط برای اقدامِ ثانویه؛ تمرکز روی CTA (`#F4A261`) بماند.

#### ۳.۴ بازخوردها و حالت‌هایِ خالی

1. **Skeleton Loading:** بلوک‌هایِ خاکستری/آبیِ کم‌رنگ به‌جای Spinner.
2. **Empty States:** آیکونِ مینیمال با `#7FE7D6` + متنِ راهنما (مثلاً «مقاله‌ای یافت نشد. کلماتِ کلیدیِ دیگری را امتحان کنید.»).
3. **Toasts:** گوشهٔ پایین، پس‌زمینه `#0B3D91` + متنِ سفید + محو شدنِ آرام بعد از **۳ ثانیه**.

#### ۳.۵ دسترس‌پذیری و کارایی

1. **Focus Ring سفارشی:** برای کیبورد (Tab) — حلقهٔ `#F4A261` دورِ المانِ فوکوس‌شده.
2. **کلیدهایِ میانبر:** برای بخش‌هایِ تخصصی (مثلاً S = ذخیرهٔ مقاله، L = لایک).
3. **Lazy Loading:** تصویر و نمودارهایِ سنگین فقط هنگامِ اسکرول.
4. **Fluid Typography:** با `clamp()` — مثلاً `font-size: clamp(1rem, 2vw, 1.5rem)` برای خواناییِ عالی در موبایل/دسکتاپ.

#### ۳.۶ اصولِ مینیمال (خلاصهٔ الزامی)

1. **حذفِ حواس‌پرتی‌ها:** هر چیزی که به خواناییِ متن یا دیدنِ داده کمک نمی‌کند، حذف شود.
2. **استفاده از فضایِ سفید:** فضایِ خالی، محتوایِ علمی را ارزشمندتر و قابل‌اعتمادتر نشان می‌دهد.
3. **انیمیشنِ هدفمند:** فقط برای نشان دادنِ تغییرِ وضعیت یا جلبِ توجه به یک اقدامِ مهم — نه سرگرمی.
4. **ثبات (Consistency):** تمامِ دکمه‌ها، کارت‌ها و فاصله‌ها در کلِ سایت یک الگویِ واحد.

#### ۴.۲ فرانت‌ماتایِ الزامی (سرِ فایل)

عنوانِ اصلی (نسلِ دوم: «X؛ Y» با لبهٔ انسانی)، عنوانِ SEO، توضیحاتِ متا (سود + وعده)، کلیدواژهٔ اصلی/فرعی، دسته‌ها، برچسب‌ها، خلاصهٔ یک‌جمله‌ای، سطحِ دشواری، زمانِ مطالعه.

#### ۴.۳ لحن

- دوستانه-فنی؛ بدونِ خودشانگیِ آکادمیک.
- تمثیل‌ها همیشه با ذکرِ **حدِّ شکست** («این تمثیل در همین‌جا می‌شکند، چون...»).
- مخاطب «تو/شما» است؛ هر جملهٔ کلیدی می‌تواند به‌صورتِ Blockquote بیاید.

#### ۴.۴ دقتِ علمی

- **حدس ممنوع.** فقط حقیقتِ قابلِ استناد.
- عددِ کمی اگر نوشته شد، واحد داشته باشد و از منبعِ اولیه برده شده باشد.
- سؤالاتِ باز واقعاً باز نگه داشته شوند (بخشِ «چه نمی‌دانیم»).

#### ۴.۵ لینک‌هایِ مرتبط

- فقط به مقالاتی که **در سایتِ زنده موجودند** (تأیید با فهرستِ اسلاگ‌هایِ REST).
- هر لینک با یک خطِ توضیحِ مشخص («چرا این مقاله») — نه صرفِ عنوان.

#### ۴.۶ تصاویر

- فقط برای مقالاتی که تصویر **واقعاً** فهم را بهتر می‌کند.
- کپشن = کادرِ HTMLِ هایلایتِ آبیِ قفل‌شده (قانونِ ۱.۷).
- **هرگز** متنِ فارسی داخلِ تصویر چاپ نمی‌شود (فونتِ فارسی در پاپ‌آپ‌هایِ تولیدِ تصویر وجود ندارد).
- دیاگرام‌هایِ علمی با پایتون رسم می‌شوند (دقیق و تکرارپذیر)، نه با AI.

#### ۴.۷ دسته‌بندی و ترتیب

- دسته‌هایِ هر مقاله فقط از REST خوانده می‌شوند (حدسِ دسته ممنوع).
- بازنویسی‌ها دسته‌هایِ ۵تایی، ترتیبِ P1 از پایه؛ دستهٔ ریاضی (88) مرحلهٔ آخر.

### قانون ۵ — قانونِ فیلترینگ و QA پس از تولید [نسخهٔ قانونی]

**حوزهٔ کاربرد:** هر خروجیِ تولیدشده (متنِ مقاله، JSON، پلاگین، تصویر) قبل از push/تحویل.

#### ۵.۱ پیش‌نیازِ تولید

1. متنِ زندهٔ مقالهٔ هدف اول fetch شود (پایهٔ بازنویسی).
2. دسته‌هایِ اسلاگ از REST خوانده شوند.
3. فهرستِ اسلاگ‌هایِ موجودِ سایت برای لینک‌سازی تازه باشد.

#### ۵.۲ فیلترهایِ متنی (الزامی — قبل از push)

| # | فیلتر | قاعده |
|---|---|---|
| 1 | اسکنِ CJK | regex `[\u4e00-\u9fff]` — صفر آلودگی |
| 2 | اسکنِ هم‌پایهٔ فارسی/لاتین | هر ترکیبِ «حرفِ فارسی+لاتین» خارج از اصطلاحاتِ تأییدشده = خطا |
| 3 | خطاهایِ تکرارشونده | مثل «برهم‌نهیی» — با برسیِ بایتی (نه چشمی) |
| 4 | برسیِ لینک‌ها | تمامِ `qpedia.ir/...` باید در فهرستِ اسلاگ‌هایِ زنده موجود باشند |
| 5 | برسیِ منابع | ۴ منبعِ واقعی با DOI/آدرسِ معتبر؛ منبعِ جعلی ممنوع |

#### ۵.۳ فیلترهایِ فنیِ خروجی (قبل از تحویلِ پلاگین/کد)

1. **آنالیزِ استاتیکِ PHP** (بررسیِ parse، ریزینگ، متنِ فارسیِ بیرونِ گیومه).
2. **Dry-run موتور** روی فایل‌هایِ واقعی (JSONها، مارکرها، موجود بودنِ تصاویر، بدونِ باقی‌مانده).
3. **ساختارِ zip:** پوشهٔ سطحِ بالاییِ یک‌تکه (الزامِ WordPress).
4. **Idempotency:** اجرایِ دوبارهٔ پلاگین باید بی‌ضرر باشد.

#### ۵.۴ پس از اعمالِ تغییراتِ سایت

1. تأییدِ کاربرِ کاربر.
2. **بررسیِ آنلاینِ خودِ agent:** fetch صفحهٔ تغییرکرده و مقایسه با آنچه باید باشد.

#### ۵.۵ قاعدهٔ شکست

اگر هر فیلتری رد شد، **push/تحویل نمی‌شود**؛ خطا گزارش می‌شود و بعد از رفع، دوباره از اولِ همان فیلتر.
