# اصلاح صفحهٔ اصلی — «تازه‌ترین مقاله‌ها» + آرشیو مقالات

تاریخ: ۲۰۲۶-۰۹-۱۸ · سایت: `qpedia.ir` · تم: `quantum-pedia-child` (فرزند GeneratePress) · کش: LiteSpeed Cache

## ⚠️ اگر کد PHP داخل خودِ صفحه چاپ شده (صفحهٔ اصلی متن کد را نشان می‌دهد)

این یعنی اسنیپت در **محتوای برگه** چسبانده شده، نه در فایل PHP. هیچ‌چیز روی سرور
اجرا نشده و دیتابیس دست‌نخورده است؛ فقط متن اضافه شده. برگرداندن:

1. پیشخوان → برگه‌ها → **Home** → ویرایش.
2. نوار بالای ویرایشگر: **بازبینی‌ها (Revisions)** ← نسخهٔ مربوط به قبل از چسباندن کد را باز کنید و **بازیابی نسخه (Restore this revision)**.
3. اگر بازنویسی پیدا نشد: منوی سه‌نقطی → «ویرایشگر کد» → کل بلوک/پاراگراف‌های حاوی متن `<?php` تا `litespeed_purge_all` را پاک کنید → به‌روزرسانی.
4. ابزارها → LiteSpeed Cache → **Purge All**.

چرا فقط «پنهان‌کردن» کافی نیست؟ داخل همان متن چسبانده‌شده تکه‌های `<script>`،
`</script>`، `<div>` و `<?php` وجود دارد؛ همین‌ها HTML صفحه را ناقص می‌کنند
(چیدمان به‌هم‌ریخته، اسکریپت‌های دیگر نصفه‌نیمه). پس باید کامل پاک شود، نه اینکه
رنگش عوض کنید یا CSS بگذارید. ضمناً اگر فیلتر `the_content` نصب باشد، همان
تکه‌ها را هم «تعمیر» سعی می‌کند و نتیجه بدتر می‌شود — اول برگه را برگردانید.

**قاعده:** کد PHP هرگز داخل برگه/نوشته نمی‌رود. جای آن `mu-plugins` یا
`functions.php` پوستهٔ فرزند است (و هیچ‌وقت در ویرایشگر بصری؛ آنجا `'` به `‘`
تبدیل می‌شود و کد می‌میرد).

## چه چیزی خراب بود

بخش «تازه‌ترین مقاله‌ها» در صفحهٔ اصلی برای همیشه روی متن
«در حال دریافت تازه‌ترین مقاله‌ها…» می‌ماند. بررسی داده‌های زنده (REST + HTML برگهٔ `home`، شناسهٔ ۲۷۹۰):

| # | مشکل | شاهد |
|---|---|---|
| ۱ | loader این بخش یک `<script>` داخل همان بلوک HTML است و هر دو عملگر `&&` در دیتابیس به شکل `&#038;&#038;` ذخیره شده‌اند. داخل `<script>` هیچ entity بازگشایی نمی‌شود ⇒ کل اسکریپت `SyntaxError` می‌گیرد و هیچ `fetch` اجرا نمی‌شود. | `wp-json/wp/v2/pages/2790` → `for(var i=0;i<list.length &#038;&#038; i<LIMIT;i++)` |
| ۲ | زنجیرهٔ fallback اسکریپت به `/topics/` ختم می‌شود، اما نوع پست `quantum_article` با `has_archive = false` ثبت شده ⇒ `/topics/` برابر ۴۰۴ است. | `wp-json/wp/v2/types/quantum_article` → `"has_archive":false` |
| ۳ | `wp/v2/posts` آرایهٔ خالی می‌دهد، چون سایت هیچ نوشته‌ای از نوع `post` ندارد (همه‌چیز در CPT است)؛ پس حتی اگر اسکریپت اجرا هم می‌شد، گزینهٔ دوم لیست را خالی می‌دید. | `wp-json/wp/v2/posts?per_page=5` → `[]` |

نکته: مسیر اصلی‌اش سالم بود — `wp-json/wp/v2/quantum_article?per_page=8&orderby=date&order=desc&_fields=link,title` داده می‌دهد. یعنی مشکل از داده یا API نبود، صرفاً اسکریپت اجرا نمی‌شد.

## چه چیزی درست شد

**رویکرد: حذف وابستگی به JS.** لیست سمت سرور رندر می‌شود و داخل همان `<div class="qp-articles" id="qp-articles">` تزریق می‌گردد؛ بدون نیاز به ویرایش برگه.

۱. `register_post_type_args` → `has_archive` روی `/topics/` (اگر برگه‌ای با این اسلاگ باشد `/articles/`)؛ `rewrite` دست نمی‌خورد تا ۲۰۱ پیوند موجود نشکنند + یک‌بار `flush_rules()`.
۲. فیلتر `the_content` روی صفحهٔ اصلی: جایگزینی `qp-loading` / `qp-error` با ردیف‌های آماده، حذف `<script>` شکسته، وصل‌کردن لینک «مشاهدهٔ همهٔ مقاله‌ها» به نشانی واقعی آرشیو.
۳. کوئری سالم: `post_type=quantum_article`, `post_status=publish`, ۸ مورد، بدون `found_rows`؛ نسخه‌های تکراری با اسلاگ `-2` حذف می‌شوند.
۴. کش ۵ دقیقه‌ای روی لیست + پاک‌شدن خودکار کش لیست و کش LiteSpeed با هر `save_post_quantum_article`.
۵. شورت‌کد `[qpedia_recent_articles limit="8"]` برای وقتی که بخواهید بلوک JS را کلاً از برگه پاک کنید.
۶. استایل مکمل با همان پالت صفحه (`--accent: #00b8e6`) و واکنش‌گرا.

## فایل‌ها

| فایل | کاربرد |
|---|---|
| **`qpedia-home-fix.tiny.php`** | **انتخاب اول.** ۱۲۷ خط: آرشیو `/topics/` + رندر سمت سرور لیست در همان کانتینر + حذف اسکریپت شکسته + پاک‌شدن کش LiteSpeed با هر ویرایش. جای نصب: `mu-plugins` یا انتهای `functions.php` پوستهٔ فرزند. |
| **`home-recent-articles.safe-js.html`** | **انتخاب دوم (فقط اگر به فایل‌ها دسترسی ندارید).** داخل بلوک HTMLِ همان برگه، در «ویرایشگر کد» چسبانده می‌شود. در کل بدنه هیچ `&` ، `||` ، `<` یا `>` نیست، پس sanitizer بلوک HTML دیگر نمی‌تواند entity‌اش کند. |
| `qpedia-home-fix.min.php` | نسخهٔ کامل: شورت‌کد، تاریخ، فالبک REST، کش ترنزینت، فیلتر تکراری‌ها، استایل مکمل، دکمهٔ ترمیم `_thumbnail_id` و حذف `-2`ها با nonce. |
| `qpedia-home-fix.php` | همان منطق در قالب کلاس + REST `/wp-json/qpedia/v1/recent` و `/recent-html` + صفحهٔ Tools → QPedia Home Fix با گزارش و پیش‌نمایش. |
| `homepage-block.html` | محتوای جایگزین بلوکِ «تازه‌ترین مقاله‌ها» در ویرایشگر کد (فقط شورت‌کد، بدون JS). نیازمند نصب یکی از فایل‌های PHP. |

اعتبارسنجی: هر سه فایل PHP با php-parser پارس شدند (بدون خطا). بدنهٔ JS با `node --check` سالم است و منطق `paint()` روی شکل واقعی پاسخ همان API تست شد: ۸ ردیف، عنوان‌ها با decode درست entity‌ها.

## نصب — کجا چسبانده شود

| راه | مسیر | نکته |
|---|---|---|
| الف (بهترین) | `wp-content/mu-plugins/qpedia-home-fix.php` | با File Manager / CPanel / FTP؛ اگر پوشهٔ `mu-plugins` نیست، بسازید. حذف فایل = بازگشت کامل. |
| ب | پیشخوان → **ظاهر → ویرایشگر پوسته** → پوستهٔ فرزند → `functions.php` → **انتهای فایل** | `<?php` دوم اضافه نکنید. یک پنجرهٔ File Manager باز بگذارید تا اگر سایت خطا داد، همان‌جا پاکش کنید. |
| پ | افزونهٔ **Code Snippets / WPCode** → اسنیپت PHP → Run everywhere | اگر فقط به پیشخوان دسترسی دارید، این امن‌ترین راه است (خطای اسنیپت را خود افزونه غیرفعال می‌کند). |

**هرگز** کد PHP را داخل محتوای برگه/نوشته یا بلوک HTML نگذارید — آنجا اجرا نمی‌شود، فقط چاپ می‌شود (و ویرایشگر بصری نقل‌قول‌ها را هم موج‌دار می‌کند).

## بازبینی بعد از نصب

1. محتوای `qpedia-home-fix.tiny.php` را در جای بالا بگذارید.
2. ابزارها → LiteSpeed Cache → **Purge All**.
3. صفحهٔ اصلی باید ۸ ردیف مقاله ببیند، کنسول تمیز باشد و `/topics/` آرشیو را باز کند.
4. تست سریع API: `qpedia.ir/wp-json/wp/v2/quantum_article?per_page=3&_fields=id,link,date`

## بازگشت به حالت قبل

فایل mu-plugin (یا اسنیپت) را بردارید و در SQL/CLI بنویسید `delete_option('qpedia_fix_flushed')` — یا فقط Settings → Permalinks → Save Changes. برای نسخهٔ کامل، کلید گزینه `qpedia_home_fix_flush` است. هیچ تغییری در محتوای دیتابیس داده نشده است.

## باقی‌ماندهٔ بدهی‌ها (داده، نه کد)

- **۷۸ مقاله** `_thumbnail_id` شکسته دارند (به شناسهٔ یک نوشته اشاره می‌کند نه یک پیوست) ⇒ تصویر شاخص‌شان عملاً کار نمی‌کند. در هر دو نسخه دکمهٔ «ترمیم تصویر شاخص شکسته» در داشبورد هست (دستی با SQL):

  ```sql
  -- پیدا کردن موارد شکسته
  SELECT pm.post_id, pm.meta_value
  FROM wp_postmeta pm
  JOIN wp_posts p ON p.ID = pm.post_id
  WHERE pm.meta_key = '_thumbnail_id'
    AND p.post_type = 'quantum_article'
    AND NOT EXISTS (SELECT 1 FROM wp_posts a WHERE a.ID = pm.meta_value AND a.post_type = 'attachment');
  ```

- **۲۳ نسخهٔ تکراری** منتشرشده با اسلاگ `-2` (بازایمپورت ۲۰۲۶-۰۹-۰۵) ⇒ باید ادغام یا به زباله‌دان بروند (در لیست تازه‌ها فعلاً فیلتر می‌شوند).
- **۹۱ پیوست بدون ALT** و تصویر شاخصِ ۱۹تاییِ ۱۴ سپتامبر ⇒ طبق استاندارد جدید، ALT فارسی و نسبت ۱۶:۹ الزامی است.
- از ۲۰۱ مقالهٔ منتشرشده، فقط **۵۲** تا استاندارد جدید را ردیف کرده‌اند (۳۳ بازنویسی‌شده + ۱۹ ایمپورت ۱۴ سپتامبر) و هیچ‌کدام هنوز تیترهای عینِ استاندارد («حواسمان به این سوءبرداشت باشد»، «مقاله‌های مرتبط Qpedia»، «چه چیزهایی را هنوز نمی‌دانیم؟») را ندارند؛ «پاسخ کوتاه» هم فقط در ۹ مقاله هست.

## قاعدهٔ جدید برای ویرایشگر

داخل بلوک «HTML سفارشی» هرگز `&&` یا `||` نگذارید (sanitizer کاراکتر `&` را entity می‌کند و JS می‌میرد). اگر به شرط چندبخشی نیاز بود، `if` تودرتو بنویسید — یا بهتر: کد را در mu-plugin بگذارید، نه در محتوای برگه.
